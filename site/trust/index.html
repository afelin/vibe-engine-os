Transparency

Trust

How to read Coreward evidence without mistaking receipts for certification. Status of product claims lives on Status; this page is the disclosure hub.

Claimed

  • Portable OSS promotion gate: bonds, house mandates, optional signed Mandate + Ward on the CI/promote engine path, zero-token gates, capsules, replay, gauntlet, MCP authorize_write.
  • Capsules and ward_decision events are tamper-evident hashes and logs — mismatch is detectable.
  • When a Mandate is present, CI/promote cannot move without Ward re-verification (product claim is limited to that path).

Not claimed

  • Not tamper-proof storage or legal/auditor certification.
  • Not a kernel IDE sandbox — Edit/Shell and soft MCP paths can bypass Ward.
  • CyberReady: Planned / fail-open when not installed — not a shipped Coreward mode.
  • Hosted HPURL verify: unclaimed until that product exists (local/comment proof still works).
  • No SOC2 / paid bounty theater in this repository.

See also the claim ledger unclaimables and status.

How to read evidence

Capsule
Run fingerprint (capsuleHash, vowsHash). Recompute locally with validate_capsule / npm run gate:validate-capsule. Evidence of what the governed run recorded — never an authorization token.
HPURL
Proof-link fragment for the receipt viewer (Proof). Helps humans inspect a run; does not replace promote re-verify.
Ward receipt
ward_decision / ward.json record ALLOW/DENY under a Mandate. Promote always re-verifies the persisted Mandate — receipts do not authorize.
